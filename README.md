# Comet Innovations website

A static site generated from templates and content files, served by a small Express server (`server.js`, `app.js`) that also handles the contact form. Hosted on Railway.

## Run locally

```sh
npm install
npm start          # builds into dist/, then serves http://localhost:3000
npm test           # builds, then runs server, contact form and site QA tests
npm run build      # build only; lists any legal facts that are not yet confirmed
```

## Where things live

| Path | What it is |
| --- | --- |
| `src/content/site.json` | Name, category, central question, office location, company LinkedIn |
| `src/content/people.json` | People profiles. The founder's name, title, biography, expertise and career experience are set here once and used on About, article bylines and structured data. Add a person only with an approved biography (and `portrait` once one exists). |
| `src/content/legal.json` | Verified company and legal facts. Leave a value empty when it is not confirmed: the site omits that sentence rather than publishing a placeholder, and the build lists it as missing. |
| `src/content/faq.json` | The About page FAQ. The FAQPage structured data is generated from the same file. |
| `src/content/insights.json` | Insights announced as forthcoming. They are listed but never linked. |
| `src/insights/*.md` | Published Insights. JSON front matter, then the article in a small Markdown subset (see `build.js`). |
| `src/pages/*.html` | Page content. `{{...}}` values come from the content files. |
| `src/layout.html`, `src/partials/` | Shared head, navigation, footer, article template and diagrams |
| `public/` | Static assets: styles, scripts, fonts, logos and images |

The build fails if a template refers to a missing value or if a placeholder such as `[COMPANY NUMBER]` would reach a page.

## Deploy on Railway

`railway.json` runs `npm run build` and then `npm start`, with a health check on `/healthz`.

Search and discovery settings (see `docs/seo-report.md`):

| Variable | Purpose |
| --- | --- |
| `REDIRECT_TO_CANONICAL` | Set to `true` once `www.comet-innovations.com` points at Railway, so the Railway address redirects to it. Until then non-canonical hosts are served with `X-Robots-Tag: noindex`. |
| `INDEXNOW_KEY` | A 32-character hex key (`openssl rand -hex 16`). Enables IndexNow notifications for pages that change in each deploy. `INDEXNOW_ENABLED=false` pauses them. |
| `SITE_URL` | Optional. Overrides the canonical origin from `site.json`, for a staging service. |

Set these variables so the contact form can email enquiries through [Resend](https://resend.com):

| Variable | Example | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | `re_...` | Resend API key |
| `CONTACT_TO_EMAIL` | `hello@example.com` | Where enquiries are delivered (comma-separate several) |
| `CONTACT_FROM_EMAIL` | `Comet Website <website@example.com>` | Sender; its domain must be verified in Resend |

## URLs, metadata and search

- Public URLs are clean (`/about`, `/insights/the-four-fundamentals`). `.html` URLs, trailing slashes, `/rd` and the bare domain redirect permanently.
- Each page declares its exact `title`, `description`, search `intent`, `ogImage`, breadcrumb `parent` and `schema` in its `<!--meta -->` header. Insights declare theirs under `seo` in the front matter. Set `modified` on an Insight only after a substantive change.
- The build writes `sitemap.xml`, `robots.txt`, `llms.txt` and a per-page JSON-LD graph. The crawler policy lives in `site.json`.
- After changing a title or adding an Insight, regenerate the social images with `node tools/generate-og.mjs`.
- `docs/seo-report.md` records the URL inventory, intents, structured data, redirects, crawler policy and open dependencies.

## Cookies and analytics

The site sets no cookies and uses no browser storage, and the Cookie Policy says so. Adding analytics needs three things together: a consent banner offering accept and reject with equal prominence, the provider listed under `analyticsProviders` in `legal.json` (which the Cookie Policy then names), and the provider's domain added to the Content Security Policy in `app.js`.

## Imagery

Photographs are named slots in `src/content/images.json`; pages reference a slot and it renders only once its graded files exist in `public/images/`. `python3 tools/grade-images.py` grades every slot whose untouched master is in `assets/source/` (natural colour with slightly eased saturation, lifted shadows, soft highlights, fine grain) and writes AVIF, WebP and a JPEG fallback; the build writes focal points to `images.css`. `node tools/image-inventory.mjs` regenerates `docs/image-inventory.md`, the list of required photographs and their status. The Four Fundamentals glyphs live in the hand-maintained sprite `public/images/icons.svg` (symbols `shen`, `akhet`, `columns`, `switch`). Social images are generated by `tools/generate-og.mjs`. See `docs/artwork-brief.md` for commissioned photography.
